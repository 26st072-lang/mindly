# Mindly

고민상담·후일담과 사진 기반 익명 토론을 나누는 반응형 웹 앱입니다. 홈에서 마음 라운지와 익명 토론으로 이동하고, 나의 보관함에서 각 공간의 글·공감·댓글을 확인합니다. 고민상담 보관함에는 내가 쓴 후일담도 포함됩니다.

AI 키 등록과 관리자 연결은 [초보자용 AI 설정 안내](docs/AI-SETUP.md)를 따라 진행합니다. 토론 API는 Cloudflare Worker와 D1, 무료 분석은 Gemini, 유료 분석은 OpenRouter의 GPT-6 Luna를 사용합니다.

## 실행

```sh
npm install
npm start
```

로컬 주소: http://127.0.0.1:4173

별도 빌드는 필요 없습니다. 정적 호스팅에는 `index.html`과 아래 실행 파일·폴더를 **함께** 올려주세요.

- `app.js`, `sync.js`, `views.js`, `interaction.js`, `audio.js`, `color-theme.js`, `account-dialogs.js`, `site-config.js`, `debate.js`
- `styles.css`, `theme.css`, `entry.css`, `color-theme.css`, `account-dialogs.css`, `community.css`
- `assets/`, `vendor/`

Firebase의 기존 인증 도메인과 Firestore 규칙은 호스팅 환경에 맞게 유지해야 합니다. `scripts/serve.mjs`는 로컬 미리보기용입니다.

## 배포용 파일 준비

```sh
npm run build
```

`dist/`에 실제 서비스에 필요한 파일만 복사하고 HTML에서 참조하는 로컬 파일이 있는지 검사합니다. 정적 호스팅의 배포 디렉터리를 `dist`로 지정하세요. 테스트, 개발 의존성, 미리보기 자료는 배포에 포함되지 않습니다.

이 빌드는 저장소에 포함된 3D 번들을 사용합니다. `scene.js`나 `visuals/`를 수정한 경우 먼저 `npm run build:scene`으로 번들을 갱신하세요.

## GitHub Pages 배포

저장소의 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 설정합니다. `main` 브랜치에 푸시하면 `.github/workflows/deploy-pages.yml`이 의존성을 설치하고 정적 사이트를 빌드한 뒤 `dist/`만 GitHub Pages에 배포합니다. **Actions → Deploy to GitHub Pages → Run workflow**에서 수동으로 다시 배포할 수도 있습니다.

게시 주소는 완료된 워크플로의 `github-pages` 환경에 표시됩니다. 화면과 이미지·스크립트는 상대 경로를 사용하므로 프로젝트 저장소의 하위 경로에서도 실행됩니다.

## 구성

- `app.js`: 기존 데이터 모델, 작성·공감·댓글·계정 기능과 상세 화면
- `sync.js`: 인증 상태 복원, 구독 수명 관리, 연결 상태와 재시도
- `views.js`: 라운지, 로그인, 공통 탐색과 상태별 화면
- `account-dialogs.js`, `account-dialogs.css`: 회원가입 모달, 키보드 포커스와 작은 화면의 내부 스크롤
- `interaction.js`: 키보드 탐색, 입력 포커스, 접근성 보완
- `entry.css`: 첫 화면·계정 화면의 높이별 반응형 배치와 CSS 3D 애니메이션
- `scene.js`, `visuals/`: 원본 표면을 보존한 입체 캐릭터와 낮·밤 장면, 표시 수명 관리
- `color-theme.js`, `color-theme.css`: 첫 화면부터 적용하는 테마 저장·전환과 앱 전체의 공통 색상
- `audio.js`: 브라우저에서 직접 합성하는 잔잔한 배경음악과 소리 제어
- `debate.js`, `community.css`: 익명 토론, 사진 분석 초안, 찬반·의견 검사 모달과 공간별 보관함
- `site-config.js`: 비밀 API 키 없이 공개 Worker 주소만 설정
- `worker/`: Firebase 로그인 검증, AI 제공자 연결, D1 저장과 관리자 모드 전환
- `assets/`: 기존 HTML에서 분리한 원본 캐릭터 이미지
- `vendor/`: 로컬에서 제공하는 morphdom, 3D 장면 번들과 라이선스

첫 화면과 로그인 화면은 화면의 너비와 높이에 맞춰 배치합니다. 정상 글자 크기의 320×480 휴대폰, 568×320 가로 화면부터 1920×1080 PC까지 18가지 크기로 스크롤·겹침·소개 문구의 두 줄 배치와 가운데 정렬을 검증합니다. 키보드가 올라오거나 사용자가 글자를 확대해 공간이 부족한 경우에는 내용을 잘라내지 않고 스크롤할 수 있습니다.

캐릭터는 `assets/mascot.png` 원본 표면과 윤곽을 그대로 사용하는 입체 부조 방식입니다. 원본에 없는 입·무늬·자세를 추가하지 않으며, 깊이에 따른 부드러운 음영과 고개·꼬리·가방의 작은 움직임만 더합니다. 미리보기와 실제 앱이 `visuals/mindy-character.js`, `visuals/mindy-stage.js`를 공유합니다. 행성 궤도와 캐릭터 아래 영어 문구는 사용하지 않습니다.

첫 화면과 로그인에는 1번 시안의 햇살 드는 상담실을 기본으로 적용했습니다. 상단 달·해 아이콘으로 나이트 모드를 전환하면 3번 시안의 책과 조명 장면이 표시됩니다. 기존 오른쪽 하트 말풍선은 두 모드에서 모두 유지합니다. 선택한 테마는 `mindly-color-theme`에 저장하며, 다음 방문 때 스타일이 그려지기 전에 복원합니다. 저장소 접근이 막혀도 현재 화면의 전환은 동작합니다.

앱 전체에 1번 시안의 옅은 청회색·따뜻한 종이색·식물색·연보라색을 사용합니다. 야간에는 본문·보조 문구·입력창·버튼·댓글·일기·오류·메뉴에 각각 대응하는 색상을 적용하고, 입력 중인 값이나 포커스 대상을 교체하지 않습니다. 나이트 모드 접근성 및 텍스트·입력 안내 대비, 모드 저장과 3D 장면 재사용, 좁은 화면의 버튼 겹침을 테스트합니다.

상단 보조 문구와 하단 설명·저작권 문구를 덜어내고, 로딩·메뉴·사이드바에도 같은 창빛과 잎 배경을 적용했습니다. 캐릭터 주변의 구체·궤도와 흩날리는 장식 입자는 사용하지 않습니다.

PC 첫 화면은 넓은 패널 안에서 제목과 캐릭터를 크게 배치하고, 하단의 세 가지 특징을 카드로 정리했습니다. 로그인 폼과 라운지의 글자·카드 크기도 넓은 화면에 맞춰 키웠으며, 1200px 이상에서는 게시글 목록을 두 열로 표시합니다. 음악 버튼에는 글씨 없이 상태별 아이콘과 색만 표시하고, 스크린리더용 이름과 켜짐 상태는 유지합니다.

배경음악은 상단 음표 버튼을 누르면 시작합니다. 부드러운 건반 음색과 긴 화음으로 직접 구성한 64초 악구를 이어서 합성하며, 외부 음원·마이크 권한·오디오 다운로드는 사용하지 않습니다. 소리는 서서히 켜지고 꺼지며, 로그인·게시판 이동 중에도 이어집니다. 모든 주요 화면의 상단에서 끌 수 있고, 숨겨진 탭에서는 소리와 예약을 멈춥니다. 새로고침 후에는 사용자 클릭으로 다시 시작합니다.

곡 이름은 **마인들리의 작은 쉼표**입니다. 기본 출력 음량을 22%에서 65%로 높였습니다. 음표 옆 정보 버튼에서 곡 설명과 음량 조절을 열 수 있으며, 설정한 음량은 다음 방문에도 적용됩니다.

장면은 별도 재생·정지 버튼 없이 자동으로 반복됩니다. 기기의 동작 줄이기 설정에서는 정지된 포즈를 표시하며, 페이지가 보이지 않거나 장면이 화면 밖에 있으면 렌더링을 중단합니다. 모바일의 픽셀 밀도와 프레임 수를 제한하고, 로그인·게시판으로 이동할 때 장면을 재사용하거나 GPU 자원을 정리합니다. 첫 프레임 전이나 WebGL 미지원 환경에서는 원본 캐릭터가 바로 표시됩니다. 계정 기능은 3D 표시와 독립적으로 동작합니다.

3D 실행 파일은 저장소에 포함되어 있어 배포 시 별도 빌드가 필요 없습니다. `scene.js` 또는 `visuals/`를 수정할 때 아래 명령으로 `vendor/entry-scene.min.js`를 갱신하세요. 독립 미리보기 HTML도 갱신하려면 `node scripts/build-3d-previews.mjs`를 실행합니다. Three.js는 0.187.0으로 고정하고 CDN 없이 제공합니다.

```sh
npm run build:scene
```

인증 확인이 끝난 뒤 데이터 구독을 시작합니다. 프로필 응답을 기다리느라 전체 목록을 막지 않으며, 빈 로컬 캐시를 실제 빈 목록으로 처리하지 않습니다. 일부 네트워크에서 Firestore 스트리밍 응답이 지연되는 문제가 재현되어 초기화 시 long polling을 사용합니다. 관련 설정은 [Firebase 공식 문서](https://firebase.google.com/docs/reference/js/firestore.firestoresettings#firestoresettings_experimentalforcelongpolling)를 참고하세요.

일기장 메뉴와 일기 데이터 구독을 제거했습니다. 로그아웃하면 개인 보관함·토론 초안·첨부 사진·의견 입력을 메모리에서 정리합니다. 고민상담 데이터의 접근 권한은 Firebase 보안 규칙, 새 토론의 접근 권한은 Worker에서 검증합니다.

## 계정과 댓글

새 회원은 이메일 없이 **아이디와 비밀번호**로 가입합니다. 아이디는 영문으로 시작하는 4–20자의 영문·숫자·밑줄이며, 대소문자를 구분하지 않습니다. 기존 이메일 계정은 가입한 이메일과 비밀번호로 계속 로그인할 수 있습니다.

기존 Firebase Authentication의 이메일/비밀번호 인증을 유지하면서 아이디를 내부 주소 `아이디@users.mindly1-52859.firebaseapp.com`에 대응시킵니다. 이 주소는 메일 수신용이 아니며 화면에는 아이디만 표시합니다. 아이디 중복은 Firebase Authentication에서 검사하고, Firestore의 사용자 프로필에는 `username`을 저장합니다. 비밀번호를 Firestore에 저장하지 않습니다. 로그인 화면은 아이디·비밀번호 입력과 로그인 버튼으로 구성하고, 아래 회원가입 버튼에서 별도 모달을 엽니다. 아이디·비밀번호 찾기는 관리자 문의 문구로 안내합니다. 본인확인 질문과 자동 복구 기능은 제공하지 않으며, 추가 서버 함수는 필요하지 않습니다.

홈에는 큰 공룡 캐릭터와 토론·고민 추천 각 1개를 표시합니다. 고민·후일담 탭은 마음 라운지에 두고, 왼쪽 메뉴는 홈 → 익명 토론 게시판 → 마음 라운지 → 나의 보관함 순서와 위치를 유지합니다.

고민·토론 모두 댓글 작성자와 관리자가 댓글을 수정·삭제할 수 있고 답글도 작성할 수 있습니다. 삭제하면 원문을 비우고 답글의 연결은 유지합니다. 게시글 작성자라는 이유로 다른 사람의 댓글을 수정·삭제할 수는 없습니다. 고민 댓글은 Firestore 트랜잭션과 접근 규칙으로, 토론 댓글은 Worker의 작성자 검사와 버전 검사로 동시 변경을 보호합니다. 토론 댓글 수정도 AI 표현 검사를 통과해야 저장되며, 수정 제안은 사용자가 직접 반영합니다.

토론 댓글의 찬성은 초록색, 반대는 주황색으로 구분합니다. 익명 번호는 주제별 첫 의견 작성 순서에 따라 `익명 1`, `익명 2`로 부여하며, 같은 사람은 답글·재작성·삭제 후 재참여에도 같은 번호를 유지합니다. 최신 삭제되지 않은 의견으로 한 사람 한 표를 집계합니다. D1의 `0002_opinion_threads.sql`은 기존 원문을 보존하고 익명 표시를 전환합니다.

화면 전환·데이터 수신·로그인·저장 중에는 상태 문구와 스피너를 표시합니다. 작업 중인 버튼은 중복 클릭을 막고, 완료되거나 실패하면 다시 사용할 수 있습니다. 동작 줄이기를 설정한 환경에서는 회전 효과 대신 상태 문구로 진행 상황을 알립니다.

운영 Firestore 규칙은 `firestore.rules`로 관리합니다. 기존 프로필·일기·후일담 권한을 유지하고, 일반 사용자는 자신의 댓글만 추가·수정·삭제할 수 있도록 검사합니다. Firebase CLI에서 `firebase deploy --only firestore:rules --project mindly1-52859`로 규칙만 배포합니다. 배포 자격 증명은 저장소에 포함하지 않습니다. `scripts/check-firestore-rules.cjs`는 설치된 Firebase CLI 모듈(`FIREBASE_TOOLS_LIB`)과 관리자 로그인을 사용해 가상 요청으로 권한 시나리오를 검사하며, 운영 문서는 변경하지 않습니다.

## 검증

```sh
npm test
```

Chrome이 설치된 환경에서 Playwright를 사용합니다. `playwright.config.mjs`의 `channel`을 환경에 맞게 변경할 수 있습니다.

테스트는 가상 Firebase 데이터를 사용하므로 실제 게시글·댓글·계정은 생성하거나 변경하지 않습니다. 인증 지연, 비어 있는 캐시, 오류와 재시도, 포커스와 초안 유지, 중복 저장, 로그아웃 정리, 탭 위치, 키보드 메뉴, 접근성, 320–1440px의 7가지 화면 너비를 확인합니다. 댓글 수정 권한·동시 추가·수정 충돌, 아이디 가입·중복·기존 이메일 로그인·프로필 저장 실패 복구, 로딩 표시의 시작과 해제도 검증합니다. 실제 서버 검증은 비로그인 읽기만 수행했습니다. 실제 계정으로 가입·로그인·댓글을 수정하는 운영 환경 검증은 별도로 필요합니다.
