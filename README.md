# Mindly

크롬 확장 프로그램의 설치와 연동 방법은 [확장 프로그램 안내](mindly-extension/README.md)를 참고하세요. 웹사이트에서는 원하는 주제를 직접 입력하거나 댓글 사진으로 토론을 만들 수 있으며, 확장 프로그램에서 가져온 글은 별도 화면에서 분석·게시합니다.

고민상담·후일담과 익명 토론을 나누는 반응형 웹 앱입니다. 토론은 사진·기존 댓글 없이 주제만으로도 AI가 배경, 쟁점과 찬반 입장의 초안을 제안하며, 사용자가 확인·수정 후 직접 게시합니다. 홈에서 마음 라운지와 익명 토론으로 이동하고, 나의 보관함에서 각 공간의 글·공감·댓글을 확인합니다. 고민상담 보관함에는 내가 쓴 후일담도 포함됩니다.

이용 대상은 **중학생과 고등학생**입니다. 회원가입, 새 고민 작성과 나이대 필터에서 이 두 항목만 선택할 수 있습니다. 기존 회원·게시글의 `elem` 나이대와 저장된 내용은 일괄 변경하거나 삭제하지 않습니다. 기존 글을 수정할 때도 나이대를 직접 바꾸지 않으면 원래 값을 유지합니다. 만 14세 이상 인증이나 보호자 동의 기능은 추가하지 않습니다.

토론 작성의 **출처 추가**에서 원문 이름과 URL을 입력할 수 있습니다. 확장 프로그램으로 가져온 출처는 자동으로 채우며, 게시 전에 수정·삭제할 수 있습니다. 책·방송 등 URL이 없는 출처는 이름만 입력할 수 있습니다. 출처는 `0005_debate_sources.sql`의 `debates.sources_json`에 토론과 함께 저장하며 상세 화면에서 원문으로 이동할 수 있습니다. 원본 사진·가져온 댓글은 저장하지 않으며, 출처 표시는 사실 검증 인증이 아닙니다.

AI 키 등록과 관리자 연결은 [초보자용 AI 설정 안내](docs/AI-SETUP.md)를 따라 진행합니다. 토론 API는 Cloudflare Worker와 D1, 무료 분석은 Gemini, 유료 분석은 OpenRouter의 GPT-6 Luna를 사용합니다.

모든 화면 하단에는 로그인 없이 볼 수 있는 상담전화와 운영자 이메일 `kickinmindly@gmail.com`, **이용 안내 및 FAQ**가 표시됩니다. 고민 작성·수정 입력창 아래에는 개인정보를 적지 말라는 안내가 표시됩니다. 마음 라운지 댓글의 욕설·비방 안내는 토론과 같은 수정 안내창을 사용하며, 원문과 답글 대상을 유지하고 확인 후 입력창으로 돌아갑니다.

이용 안내 및 FAQ는 메뉴나 하단에서 열 수 있습니다. 기존 관리자 계정으로 로그인한 뒤 **관리자 → 이용 안내 및 FAQ 수정하기 → 안내 및 FAQ 수정**에서 각 항목을 편집하고 **변경 내용 저장**을 누르세요. 저장 내용은 기존 Firestore `meta/help` 문서의 `sections`에 보관되어 비로그인 사용자에게도 반영됩니다. 아직 저장하지 않았다면 기본 안내를 보여줍니다. 기존 `meta`의 공개 읽기·관리자 쓰기 규칙을 사용하므로 DB 마이그레이션, API 변경, 로그인 설정 변경은 필요하지 않습니다. 문의용 이메일과 관리자 인증 계정 설정은 별개입니다.

## 실행

```sh
npm install
npm start
```

로컬 주소: http://127.0.0.1:4173

별도 빌드는 필요 없습니다. 정적 호스팅에는 `index.html`과 아래 실행 파일·폴더를 **함께** 올려주세요.

- `app.js`, `sync.js`, `views.js`, `interaction.js`, `audio.js`, `color-theme.js`, `account-dialogs.js`, `site-config.js`, `debate.js`
- `styles.css`, `theme.css`, `entry.css`, `color-theme.css`, `account-dialogs.css`, `community.css`
- `assets/`, `vendor/`

Firebase의 기존 인증 도메인과 Firestore 규칙은 호스팅 환경에 맞게 유지해야 합니다. `scripts/serve.mjs`는 로컬 미리보기용입니다.

## 배포용 파일 준비

```sh
npm run build
```

`dist/`에 실제 서비스에 필요한 파일만 복사하고 HTML에서 참조하는 로컬 파일이 있는지 검사합니다. 정적 호스팅의 배포 디렉터리를 `dist`로 지정하세요. 테스트, 개발 의존성, 미리보기 자료는 배포에 포함되지 않습니다.

홈·첫 화면·로그인은 원본 캐릭터 이미지와 같은 창가 구성요소를 사용하며, 별도 3D 번들을 불러오지 않습니다. 독립 3D 미리보기의 `scene.js`나 `visuals/`를 수정하는 경우에만 `npm run build:scene`으로 번들을 갱신하세요.

## GitHub Pages 배포

저장소의 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 설정합니다. `main` 브랜치에 푸시하면 `.github/workflows/deploy-pages.yml`이 의존성을 설치하고 정적 사이트를 빌드한 뒤 `dist/`만 GitHub Pages에 배포합니다. **Actions → Deploy to GitHub Pages → Run workflow**에서 수동으로 다시 배포할 수도 있습니다.

게시 주소는 완료된 워크플로의 `github-pages` 환경에 표시됩니다. 화면과 이미지·스크립트는 상대 경로를 사용하므로 프로젝트 저장소의 하위 경로에서도 실행됩니다.

## 구성

- `app.js`: 기존 데이터 모델, 작성·공감·댓글·계정 기능과 상세 화면
- `sync.js`: 인증 상태 복원, 구독 수명 관리, 연결 상태와 재시도
- `views.js`: 라운지, 로그인, 공통 탐색과 상태별 화면
- `account-dialogs.js`, `account-dialogs.css`: 회원가입 모달, 키보드 포커스와 작은 화면의 내부 스크롤
- `interaction.js`: 키보드 탐색, 입력 포커스, 접근성 보완
- `entry.css`: 첫 화면·계정 화면의 높이별 반응형 배치
- `scene.js`, `visuals/`: 독립 3D 미리보기의 입체 캐릭터와 낮·밤 장면
- `color-theme.js`, `color-theme.css`: 첫 화면부터 적용하는 테마 저장·전환과 앱 전체의 공통 색상
- `audio.js`: 브라우저에서 직접 합성하는 잔잔한 배경음악과 소리 제어
- `debate.js`, `community.css`: 익명 토론, 사진 분석 초안, 찬반·의견 검사 모달과 공간별 보관함
- `site-config.js`: 비밀 API 키 없이 공개 Worker 주소만 설정
- `worker/`: Firebase 로그인 검증, AI 제공자 연결, D1 저장과 관리자 모드 전환
- `assets/`: 기존 HTML에서 분리한 원본 캐릭터 이미지
- `vendor/`: 로컬에서 제공하는 morphdom, 3D 장면 번들과 라이선스

첫 화면과 로그인 화면은 화면의 너비와 높이에 맞춰 배치합니다. 정상 글자 크기의 320×480 휴대폰, 568×320 가로 화면부터 1920×1080 PC까지 18가지 크기로 스크롤·겹침·소개 문구의 두 줄 배치와 가운데 정렬을 검증합니다. 키보드가 올라오거나 사용자가 글자를 확대해 공간이 부족한 경우에는 내용을 잘라내지 않고 스크롤할 수 있습니다.

홈·첫 화면·로그인은 `assets/mascot.png` 원본을 변경하지 않고 같은 둥근 창가에 표시합니다. `mascotScene('home')`을 공유하며, 크기에 따라 창틀·창살·캐릭터·받침대가 함께 비례해 표시됩니다. 창 뒤의 타원형 빛과 유리 위의 흰 조명·안개를 없애고, 유리는 고른 푸른색으로 정리했습니다.

상단 달·해 아이콘으로 나이트 모드를 전환하면 같은 창가의 색상을 야간용으로 바꿉니다. 선택한 테마는 `mindly-color-theme`에 저장하며, 다음 방문 때 스타일이 그려지기 전에 복원합니다. 저장소 접근이 막혀도 현재 화면의 전환은 동작합니다.

앱 전체에 옅은 청회색·따뜻한 종이색·식물색·연보라색을 사용합니다. 야간에는 본문·보조 문구·입력창·버튼·댓글·일기·오류·메뉴에 각각 대응하는 색상을 적용하고, 입력 중인 값이나 포커스 대상을 교체하지 않습니다. 나이트 모드 접근성 및 텍스트·입력 안내 대비, 모드 저장과 창가 구성 유지, 좁은 화면의 버튼 겹침을 테스트합니다.

상단 보조 문구와 하단 설명·저작권 문구를 덜어내고, 로딩·메뉴·사이드바에도 같은 창빛과 잎 배경을 적용했습니다. 캐릭터 주변의 구체·궤도와 흩날리는 장식 입자는 사용하지 않습니다.

PC 첫 화면은 넓은 패널 안에서 제목과 캐릭터를 크게 배치하고, 하단의 세 가지 특징을 카드로 정리했습니다. 로그인 폼과 라운지의 글자·카드 크기도 넓은 화면에 맞춰 키웠으며, 1200px 이상에서는 게시글 목록을 두 열로 표시합니다. 음악 버튼에는 글씨 없이 상태별 아이콘과 색만 표시하고, 스크린리더용 이름과 켜짐 상태는 유지합니다.

배경음악은 상단 음표 버튼을 누르면 시작합니다. 부드러운 건반 음색과 긴 화음으로 직접 구성한 64초 악구를 이어서 합성하며, 외부 음원·마이크 권한·오디오 다운로드는 사용하지 않습니다. 소리는 서서히 켜지고 꺼지며, 로그인·게시판 이동 중에도 이어집니다. 모든 주요 화면의 상단에서 끌 수 있고, 숨겨진 탭에서는 소리와 예약을 멈춥니다. 새로고침 후에는 사용자 클릭으로 다시 시작합니다.

곡 이름은 **마인들리의 작은 쉼표**입니다. 기본 출력 음량을 22%에서 65%로 높였습니다. 음표 옆 정보 버튼에서 곡 설명과 음량 조절을 열 수 있으며, 설정한 음량은 다음 방문에도 적용됩니다.

창가와 원본 캐릭터는 처음부터 같은 모습으로 표시되며, 시간이 지나도 3D로 바뀌지 않습니다. WebGL 없이 로그인과 화면 전환을 사용할 수 있습니다.

독립 3D 미리보기의 `scene.js` 또는 `visuals/`를 수정할 때는 아래 명령으로 `vendor/entry-scene.min.js`를 갱신하세요. 독립 미리보기 HTML도 갱신하려면 `node scripts/build-3d-previews.mjs`를 실행합니다. Three.js는 0.187.0으로 고정하고 CDN 없이 제공합니다.

```sh
npm run build:scene
```

인증 확인이 끝난 뒤 데이터 구독을 시작합니다. 프로필 응답을 기다리느라 전체 목록을 막지 않으며, 빈 로컬 캐시를 실제 빈 목록으로 처리하지 않습니다. 일부 네트워크에서 Firestore 스트리밍 응답이 지연되는 문제가 재현되어 초기화 시 long polling을 사용합니다. 관련 설정은 [Firebase 공식 문서](https://firebase.google.com/docs/reference/js/firestore.firestoresettings#firestoresettings_experimentalforcelongpolling)를 참고하세요.

일기장 메뉴와 일기 데이터 구독을 제거했습니다. 로그아웃하면 개인 보관함·토론 초안·첨부 사진·의견 입력을 메모리에서 정리합니다. 고민상담 데이터의 접근 권한은 Firebase 보안 규칙, 새 토론의 접근 권한은 Worker에서 검증합니다.

## 계정과 댓글

새 회원은 이메일 없이 **아이디와 비밀번호**로 가입합니다. 아이디는 영문으로 시작하는 4–20자의 영문·숫자·밑줄이며, 대소문자를 구분하지 않습니다. 기존 이메일 계정은 가입한 이메일과 비밀번호로 계속 로그인할 수 있습니다.

기존 Firebase Authentication의 이메일/비밀번호 인증을 유지하면서 아이디를 내부 주소 `아이디@users.mindly1-52859.firebaseapp.com`에 대응시킵니다. 이 주소는 메일 수신용이 아니며 화면에는 아이디만 표시합니다. 아이디 중복은 Firebase Authentication에서 검사하고, Firestore의 사용자 프로필에는 `username`을 저장합니다. 비밀번호를 Firestore에 저장하지 않습니다. 로그인 화면은 아이디·비밀번호 입력과 로그인 버튼으로 구성하고, 아래 회원가입 버튼에서 별도 모달을 엽니다. 아이디·비밀번호 찾기는 관리자 문의 문구로 안내합니다. 본인확인 질문과 자동 복구 기능은 제공하지 않으며, 추가 서버 함수는 필요하지 않습니다.

홈에는 큰 공룡 캐릭터와 토론·고민 추천 각 1개를 표시합니다. 고민·후일담 탭은 마음 라운지에 두고, 왼쪽 메뉴는 홈 → 익명 토론 게시판 → 마음 라운지 → 나의 보관함 순서를 유지하며 화면 왼쪽 끝에 붙입니다. 휴대폰에서는 홈·첫 화면·로그인 화면의 워드마크를 가운데에 정렬합니다.

상단 검색은 고민상담과 익명 토론을 한 화면의 두 탭으로 나누어 표시합니다. 고민은 제목·본문·해시태그를, 토론은 서버에서 제목·배경·쟁점을 검색하므로 첫 목록 20개보다 오래된 토론도 찾을 수 있습니다. 토론 결과는 페이지별로 추가 조회하며, 이전 검색 응답이 늦게 도착해도 새 결과를 덮어쓰지 않습니다.

고민 댓글은 작성자와 관리자가 수정·삭제할 수 있습니다. 익명 토론 댓글은 작성자 본인만 수정할 수 있으며 관리자는 다른 사람의 댓글을 삭제할 수 있습니다. 관리자 삭제 시 ‘관리자에 의해 삭제된 댓글입니다’를 표시합니다. 삭제는 원문을 비우고 답글의 연결을 보존하며, 관리자 자신의 댓글 삭제는 일반 삭제로 표시합니다. 이 구분은 `0003_comment_moderation.sql`로 추가한 열에 저장합니다. 게시글 작성자라는 이유로 다른 사람의 댓글을 수정·삭제할 수는 없습니다. 고민 댓글은 Firestore 트랜잭션과 접근 규칙으로, 토론 댓글은 Worker의 작성자 검사와 버전 검사로 동시 변경을 보호합니다. 토론 댓글 수정도 AI 표현 검사를 통과해야 저장되며, 수정 제안은 사용자가 직접 반영합니다.

마음 라운지는 상황에 대한 가벼운 욕설·감정 표현을 허용하고, 사람을 향한 욕설·모욕·외모 및 정신질환 비하·위협을 검사합니다. ‘개같네’, ‘아 개빡쳐’, ‘존나 힘들겠다’는 허용하며, ‘미친년’, ‘개새끼’, ‘정신병 있냐’, ‘찐따 같아’, ‘너 못생김’은 차단합니다. 정규화와 변형 사전으로 띄어쓰기·기호·초성·유사 발음·분리된 한글 우회도 확인합니다. 자기 감정, 상황 비판, 부정·위로와 피해 경험 인용은 해당 구절의 문맥을 살펴 허용하며, 인용 뒤에 덧붙인 새로운 공격은 따로 검사합니다. 규칙 기반 방식이므로 모든 문맥을 완벽하게 이해하는 것은 아닙니다.

차단 시 ‘다른 사람에게 상처를 주는 표현은 수정해 주세요.’를 표시합니다. 마음 라운지 안내창에는 표현 제안 영역을 표시하지 않고 입력한 내용과 답글 대상을 보존합니다. 익명 토론의 기존 AI 필터·표현 제안은 유지합니다. 라운지는 새 AI API를 호출하지 않으며 별도 외부 분석 서비스에 내용을 전송하지 않습니다. 근거 첨부 버튼은 라운지 댓글·답글·수정 화면에서 표시하지 않고, 기존 첨부 자료는 수정해도 보존합니다.

필터 원본은 `scripts/concern-policy.mjs`이며 `npm run build:filter`가 `concern-filter.js`와 `firestore.rules`의 필터 부분을 함께 생성합니다. 정적 빌드는 두 결과의 동기화를 검사합니다. Firestore 보안 규칙도 신규·수정 댓글을 검사하므로 클라이언트를 건너뛴 직접 저장은 거부됩니다. 기존 댓글은 재검사해 삭제하지 않으며 공감·게시글 수정 등은 계속 이용할 수 있습니다. 변경 시 웹사이트와 `firestore:rules`를 함께 배포해야 합니다. `worker/tests/concern-filter.test.mjs`는 허용·차단·오탐·인용·우회 사례를, `scripts/check-firestore-emulator.mjs`는 로컬 `demo-mindly` 에뮬레이터(127.0.0.1:8180)에서 직접 저장·권한·기존 데이터 보존을 검사합니다.

토론 댓글의 찬성은 마인들리 파란색, 반대는 흰색 배경으로 구분하며 야간에는 같은 계열의 어두운 색을 사용합니다. 댓글의 여백을 줄이고 수정·삭제·답글 버튼은 오른쪽에 배치합니다. 본문이 화면에서 다섯 줄을 넘으면 ‘더보기’로 펼칠 수 있고, 다시 접을 수 있습니다. 고민·토론 댓글의 최대 길이는 1000자이며 토론은 작성·답글·수정을 서버에서도 검사합니다. 토론 답글은 선택한 댓글 바로 아래에서 별도의 찬반과 내용을 작성하므로 상단 의견 초안과 섞이지 않습니다.

익명 번호는 주제별 첫 의견 작성 순서에 따라 `익명 1`, `익명 2`로 부여하며, 같은 사람은 답글·재작성·삭제 후 재참여에도 같은 번호를 유지합니다. 최신 삭제되지 않은 의견으로 한 사람 한 표를 집계합니다. D1의 `0002_opinion_threads.sql`은 기존 원문을 보존하고 익명 표시를 전환합니다.

화면 전환·데이터 수신·로그인·저장 중에는 상태 문구와 스피너를 표시합니다. 작업 중인 버튼은 중복 클릭을 막고, 완료되거나 실패하면 다시 사용할 수 있습니다. 동작 줄이기를 설정한 환경에서는 회전 효과 대신 상태 문구로 진행 상황을 알립니다.

운영 Firestore 규칙은 `firestore.rules`로 관리합니다. 기존 프로필·일기·후일담 권한을 유지하고, 일반 사용자는 자신의 댓글만 추가·수정·삭제할 수 있도록 검사합니다. Firebase CLI에서 `firebase deploy --only firestore:rules --project mindly1-52859`로 규칙만 배포합니다. 배포 자격 증명은 저장소에 포함하지 않습니다. `scripts/check-firestore-rules.cjs`는 설치된 Firebase CLI 모듈(`FIREBASE_TOOLS_LIB`)과 관리자 로그인을 사용해 가상 요청으로 권한 시나리오를 검사하며, 운영 문서는 변경하지 않습니다.
